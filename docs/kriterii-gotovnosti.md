# Критерии готовности Trafaret Line

Версия 1.0 от 15.10.2026. Часть считается готовой, когда выполнены общие критерии для каждого PR и критерии «готово, когда…» самой части. Сайт готов к запуску на 100 %, когда готовы все части из раздела 2 и закрыт список «Что решает только Денис» в `PROEKT-SAYTU.md`.

## 1. Общие критерии для каждого PR

Проверяет GitHub CI (`.github/workflows/ci.yml`), PR с красной проверкой не сливаем.

1. Типы без ошибок: `web` — `npm run typecheck`, `backend` — `npm run typecheck`.
2. Линтер без ошибок и предупреждений: `npx eslint . --max-warnings 0` в `web`.
3. Сборки проходят: `npm run build` в `web` и `backend`.
4. Юнит-тесты зелёные: `npm test` в `web` (Vitest, `web/tests/unit`).
5. Сквозные тесты зелёные: `npm run test:e2e` в `web` (Playwright, `web/tests/e2e`, магазин и оплата подменены, ключи не нужны).
6. Тест backend на PostgreSQL зелёный: `npm run test:integration:http`.
7. Дублирование кода не выше 1,5 %: `npx jscpd@4.3.0 --config .jscpd.json`.

Проверяет автор PR (и ревьюер):

8. Код полный: без заглушек, `TODO`, «потом доделаем», закомментированного кода (правило Дениса 09.10).
9. Одна логическая функция — один файл в `web/lib` или `web/services`; все типы в `web/types` (вход `types/index.ts`); маршруты в `web/app`.
10. Общий код для backend пишется только в `web/lib` и `web/types` с относительными импортами; `backend/src/shared` собирается скриптом и руками не правится. Ставки, плотности, упаковка и данные продавца меняются только в `web/data/knowledge_base/*.json`.
11. Новая формула цены, размера или проверки покрыта юнит-тестом; новый путь покупки покрыт сквозным тестом.
12. Покупатель нигде не видит м² и ₴/м²; поставщик материалов не упоминается; для PET нет слов «харчовий» и «сертифікований».
13. Ключи, пароли и логины в коде и в файлах проекта отсутствуют.
14. Текст интерфейса на украинском, без ошибок, термины как на остальном сайте.
15. Работает на телефоне шириной 360 px и на компьютере: нет горизонтальной прокрутки, кнопки не меньше 44 px.

## 2. Части сайта: «готово, когда…»

Колонка «Чем проверено» говорит, какой автотест держит критерий. Пусто — проверяется руками при приёмке.

### Каталог и карточка товара
| Часть | Готово, когда… | Чем проверено |
| --- | --- | --- |
| Раздел и подраздел | Раздел открывается по своему адресу, показывает заголовок, число товаров и карточки с ценой «від …»; фильтр по материалу и сортировка меняют список без перезагрузки | `e2e/catalog.spec.ts` (заголовок, число, переход в товар) |

| Поиск | По двум и более буквам находит товары по названию и описанию; пустой запрос не ломает страницу | |
| Заготовки `/zahotovky` | Пошаговый выбор форма → размер → материал → толщина → цвет, цена по ставкам ТЗ §21, минимум 150/250 ₴ | |

### Корзина и оформление
| Часть | Готово, когда… | Чем проверено |
| --- | --- | --- |
| Корзина | Открывается после добавления, показывает строки, количество меняется, подсказка до следующей скидки верная; переход к оформлению сохраняет строки | `e2e/catalog.spec.ts`, `e2e/checkout.spec.ts` |
| Оформление | Четыре обязательных поля; пустое поле подсвечивается и получает фокус, заказ не уходит; после заказа корзина пуста, повторная отправка невозможна | `e2e/checkout.spec.ts` |

| Оплата картой (WayForPay) | Заказ создаётся, подписанная форма уходит на WayForPay, «Дякуємо» только после оплаты; если оплата не запустилась — заказ сохранён и есть «Спробувати ще раз» | `e2e/checkout.spec.ts` (WayForPay подменён) |

| Рахунок для ФОП/ТОВ | Реквизиты по ЄДРПОУ подтягиваются, счёт открывается по ссылке с токеном и сохраняется в PDF | |
